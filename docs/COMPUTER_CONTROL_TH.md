# ควบคุมเครื่อง — Uncle Desktop

ตรวจเทียบ source 0.23.10 วันที่ 1 พฤศจิกายน 2026; การมี native helper ไม่ใช่การยืนยันทุกแอป/ทุกแพลตฟอร์มผ่านการทดสอบจริง

## เริ่มใช้งาน

1. เปิด **ตั้งค่า › ควบคุมเครื่อง** หรือเมนูงานควบคุมเครื่อง
2. อนุญาตอ่านหน้าต่าง/ใช้เมาส์คีย์บอร์ด เลือกความปลอดภัยและสวิตช์ตามงาน หากใช้ภาพต้องอนุญาตภาพและเลือกโมเดลที่รับภาพได้
3. ระบุงาน เช่น “เปิด Notepad แล้วพิมพ์ สวัสดีจาก Uncle” แล้วเริ่ม AI ใช้ provider/model สำหรับงานควบคุมที่ตั้งไว้ ณ ตอนเริ่มงาน
4. อ่านรายการขั้นตอนและคำถามก่อนยืนยัน คำตอบหลังหมดเวลาหรือหยุดงานจะไม่เริ่มขั้นตอนต่อ

รองรับ Gemini, OpenAI-compatible และ Ollama สำหรับวางแผนงาน ไม่ใช้ Claude chat provider ในวงจรนี้ คำสั่งระบบบางชนิดทำผ่านเครื่องมือโดยตรง จึงไม่ต้องใช้โมเดลเดาปุ่ม เช่นคำสั่งเสียง Windows ที่ตรวจสิทธิ์แล้ว

## ขอบเขตแพลตฟอร์ม

| ระบบ | ทางเชื่อม native | ต้องตรวจ |
|---|---|---|
| Windows | PowerShell + C# / UI Automation | การเข้าถึง UIA, แอป/เกมที่ไม่เปิด accessibility, media session และระดับเสียงจริง |
| macOS | Swift helper + Accessibility / System Events | helper ที่แพ็กกับแอป, สิทธิ์ Accessibility/Screen Recording และคำสั่ง media/power ที่ต่างจาก Windows |

บน macOS ชื่อคีย์ CTRL ในคำสั่ง native หมายถึง Command; ALT หมายถึง Option คีย์ลัดระบบ/ชื่อหน้าต่าง/คำสั่งพลังงานบางอย่างต่างกัน ดู [ติดตั้งบน Mac](INSTALL_MAC_TH.md) ไม่มีผลตรวจบน Windows ใดใช้รับรอง Mac ได้

## งานที่มีเครื่องมือรองรับ

| กลุ่ม | ความสามารถ |
|---|---|
| อ่านและวางแผน | อ่านหน้าต่าง/เป้าหมาย, focus, note ข้อความที่เห็น, wait/wait_for, ask และจบพร้อมหลักฐาน |
| เมาส์/คีย์บอร์ด | คลิกซ้าย/ขวา/กลาง/สองครั้ง/สามครั้ง, ย้ายเมาส์, cursor position, ลาก, พิมพ์ Unicode, กด/กดค้าง/กดร่วม, เลื่อน |
| แอป/เว็บ | เปิดแอปหรือเว็บไซต์, ค้นหาเว็บ, ย่อ/focus/ปิดแอปแบบปกติ |
| เพลงและเสียง | เล่นพัก/ถัดไป/ก่อนหน้า, ค้นหา Spotify/YouTube, อ่าน media session, volume/mute ตาม backend ของระบบ |
| ระบบ/ตัวละคร | คีย์ลัดที่อนุญาต, จำ/ลืมข้อมูล, พลังงานเครื่อง, หลับ/ตื่น/ซ่อน/ย้าย/เต้นตามท่าที่ตัวละครมี |

พิกัดจากภาพตรวจขอบเขตกับภาพหน้าต่าง ไม่ใช่ตำแหน่งตามจินตนาการของ AI การทำงานกับเกม/custom canvas อาจไม่อ่านข้อความหรือหลักฐานได้ ไม่รับประกันทุกเว็บหรือทุกแอป ไม่รัน shell/script และไม่พิมพ์คำสั่งใน console/Run

## ความปลอดภัยและการยืนยัน

มี 4 presets: `lockdown` อ่านอย่างเดียว; `guarded` อนุญาตงานพื้นฐานบางกลุ่ม; `trusted` และ `blackwall` เปิดการทำงานอัตโนมัติมากขึ้น มีสวิตช์การกระทำ 9 กลุ่มและสวิตช์ส่งภาพแยกอีก 1 การยืนยันขึ้นกับสวิตช์ จึงไม่ใช่ทุกระดับถามก่อนการกระทำเดียวกันเสมอ

- ทุกระดับยังปฏิเสธการกรอกช่องรหัสผ่านและการพิมพ์ใน console/Run ตรวจเป้าหมายและปกปิดค่าลับที่ระบบระบุได้; หากพบช่องลับใน observation จะงดภาพหน้าต่างนั้น
- การตรวจชื่อปุ่มเสี่ยงเป็นกฎ ไม่ใช่การจำแนกผลกระทบครบทุกภาษา ต้องอ่านรายละเอียดก่อนยืนยัน
- คำตอบผูกกับ job/approval ID และตรวจอีกครั้งก่อนลงมือ งานบนคอมรอยืนยันประมาณ 60 วินาที งาน remote ประมาณ 5 นาที
- จำกัดงาน 30 ขั้นและ 10 นาที หยุดเมื่อหน้าต่าง/เป้าหมายเปลี่ยน เครื่องมือค้าง ทำซ้ำ หรือผลไม่ผ่านเงื่อนไข
- `done` ต้องมีข้อความหลักฐานที่ตรวจจาก observation/receipt; งานภาพล้วนต้องมีการตรวจภาพแยก “รับงานแล้ว” ไม่ใช่ “สำเร็จแล้ว”
- ข้อมูลหน้าต่าง/ภาพที่อนุญาตส่งให้ AI provider ที่เลือก การเปลี่ยน provider ต้องอนุญาตใหม่ ขั้นตอนและภาพงานไม่เพิ่ม screenshot/history ไฟล์งานลงดิสก์

Windows shutdown/restart ใช้การตั้งเวลา 30 วินาทีและมี cancel; macOS ใช้คำสั่งของระบบซึ่งไม่ใช่ตัวตั้งเวลาแบบเดียวกัน ไม่ควรทดลอง power actions กับเครื่องผู้ใช้เพื่อ QA ทั่วไป

## สั่งและยืนยันด้วยเสียง

ตั้ง AI, [เสียงพูด](SPEECH_TH.md) และ [ไมค์](VOICE_COMMANDS_TH.md) แล้วเปิด **ให้คำสั่งเสียงเริ่มงานได้อัตโนมัติ** ตาม consent ที่ต้องการ คำสั่งง่ายใช้ parser/เครื่องมือเดิม งานหลายขั้นตอนเข้าสู่วงจรควบคุมเครื่อง ถ้าข้อมูลไม่ครบจะถามเพิ่ม การยืนยันจากเสียงใช้คำตอบปัจจุบัน ไม่ใช้ transcript เก่า

ระบบ Uncle เดิมพักรับเสียงระหว่าง TTS เพื่อกันการฟังตัวเอง เมื่ออยู่ช่วงรับคำสั่งระหว่างงานพูด “หยุดงาน” ได้; ใช้ **Ctrl+Alt+X** หรือปุ่มหยุดเมื่อต้องหยุดทันที ส่วน [ElevenLabs Voice Agent](VOICE_AGENT_TH.md) รองรับการพูดแทรกตามวงจรของระบบนั้น

งานจากมือถือใช้สิทธิ์บนคอมร่วมกับ Telegram User ID, PIN ตามสวิตช์ และการยืนยันคำถามจากงาน ดู [Telegram](TELEGRAM_TH.md)

## การทดสอบและที่มา

- `npm test` ตรวจ parser, ขอบเขต, consent, confirmations, cancel/late result และหลักฐานด้วย fixtures
- `npm run test:computer:live` ใช้หน้าต่าง QA จริงบน Windows; ตรวจ prerequisites และผลต่อระบบก่อนเรียก
- `scripts/live-computer-test.js` / `scripts/smoke-computer-app.js` มีการใช้ provider/native จริง ต้องใช้เฉพาะเมื่องานได้รับอนุญาตครอบคลุมการทดสอบนั้น
- หลักฐาน QA รุ่นก่อนอยู่ [archive](archive/QA_HISTORY_TH.md) งานจริงที่ยังต้องตรวจอยู่ [แผนหลัก](ROADMAP_TH.md) ไม่ถือว่ารอบจัดเอกสารนี้ได้ทดสอบควบคุมเครื่องซ้ำ

ใช้ Electron เดิมและ native helpers ขนาดเล็ก ไม่ยก WinForms UI มาแทน อ้างอิงแนวคิด observe/action/job และหมวด tools จาก Capri โดย Lachy: [app/Computer.cs และ Hands.cs](https://github.com/lachydotmcg/capri-desktop) ไม่ใช่การย้ายพารามิเตอร์หรือความสามารถทุกตัว และยังไม่มีผล benchmark เปรียบเทียบชุดงานเดียวกัน
