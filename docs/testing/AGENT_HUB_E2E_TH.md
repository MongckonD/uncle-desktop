## วิธีทดสอบ

ใช้สกิล computer-use ผ่าน Telegram Desktop ที่เปิดแชตบอตของผู้ใช้อยู่ ไม่ได้ใช้ Telegram mock และไม่ได้ควบคุมแอปบนโทรศัพท์ เปิด Electron จาก checkout ปัจจุบัน ไม่ใช่ installer 0.23.9

สร้างโปรเจกต์ด้วย `/create hub-loop-20261101-a codex` ผ่าน Telegram จริง โฟลเดอร์ที่แอปสร้างคือ `C:/Users/pk_11/vibe-projects/hub-loop-20261101-a` ตาม workspace เริ่มต้นของแอป ไม่ได้เปลี่ยน workspace หรือโมเดลที่ผู้ใช้ตั้งไว้

โจทย์: Node.js ฟังก์ชัน sum รับ finite numbers, โยน TypeError สำหรับ input ผิด, มี node:test, package.json และ README ไม่มี dependency เพิ่ม ห้าม commit/push และห้ามแก้นอกโปรเจกต์ ทุกไฟล์โค้ด/เอกสารของ demo สร้างโดย Agent จากคำสั่งใน Telegram ผู้ทดสอบอ่านไฟล์และรัน tests แยกเพื่อยืนยันผล ไม่เขียน implementation ให้ Agent แทน

## จุดที่ยังต้องแก้หรือตรวจต่อ

1. **Codex model readiness:** ควรตรวจโมเดล/บัญชีที่ใช้ได้ก่อนประกาศว่าพร้อมรับงาน หรือมีข้อความแนะนำให้เลือกโมเดลที่รองรับ รอบนี้ไม่ได้แก้โมเดลผู้ใช้และไม่ถือว่า Codex ผ่าน full loop
2. **Interrupt UX:** Claude จบรอบด้วย error หลัง interrupt จึงมีข้อความ “ทำไม่สำเร็จ” ตามหลัง “สั่งหยุดรอบนี้แล้ว” ควรแยกการหยุดโดยผู้ใช้ออกจากข้อผิดพลาด
3. **ยังไม่ครอบคลุม:** โทรศัพท์จริง, macOS, installed app, ตอบอนุมัติสลับระหว่างคอม/มือถือ, หลายผู้ใช้/หลาย session พร้อมกัน, รูปและเสียงเข้า Agent, approval ทุกชนิด และการทดสอบ timeout/CLI ล้มแบบบังคับในแอปจริง ยังอ้างอิง automated tests สำหรับกรณีเหล่านั้น
4. โฟลเดอร์ demo และ resume metadata ยังคงอยู่ Selected project ของ Vibecode เปลี่ยนเป็น demo จากคำสั่งทดสอบตามปกติของแอป ไม่มีการเปลี่ยน keys/PIN/allowlist/model settings

## ผลตรวจเพิ่มเติม 2 พฤศจิกายน 2026

ทดสอบบน Windows ด้วย Telegram Desktop และ source app หลังแก้ไข โดยสร้างโปรเจกต์แยก `C:/Users/pk_11/vibe-projects/hub-full-20261101-b` ผ่าน `/create` ผลครั้งก่อนด้านบนเป็นประวัติ ณ เวลานั้น

- Codex เลือกโมเดลเริ่มต้นที่บัญชีแจ้งว่ารองรับได้จริง เปิด session แล้วสร้างโปรเจกต์ Node.js ตามคำสั่ง อนุมัติการแก้ไฟล์และรัน `npm test` ผ่าน Telegram; ตรวจซ้ำบนเครื่องผ่าน 3/3
- `/agents`, `/diff` และ `/commit` ผ่าน Telegram; commit อยู่เฉพาะ Git repository ของโปรเจกต์ทดสอบ ปิดและ `/resume` แล้ว Codex จำบริบทและผลทดสอบเดิมได้
- `/interrupt` ระหว่างรออนุมัติแก้ไฟล์แสดงว่าหยุดโดยผู้ใช้ คำขอหมดอายุ ตรวจแล้วไฟล์ไม่ถูกสร้าง และรับงานใหม่ได้ จากนั้นปิด session ทดสอบด้วย `/end`
- Agent อ่านภาพที่มีอยู่ใน path ของโปรเจกต์และตอบจากภาพจริงได้ กรณีนี้ยังไม่ใช่การส่งภาพแนบผ่าน Telegram
- ตรวจการกู้หลัง process ขัดข้องจริง: ปิดเฉพาะ Codex app-server ที่เป็นลูกของ source app ใน session ทดสอบขณะว่าง บอตแจ้งปิด session จากนั้น `/resume` แล้วตอบรหัสจากบริบทเดิมได้ ไม่ได้จำลองการหลุดระหว่างรออนุมัติหรือการขัดข้องของเครือข่าย
- ชุดทดสอบ `npm test` ของ source ผ่าน 195 ข้าม 3 ล้มเหลว 0 รวมกรณี session หลายแชต การอนุมัติหมดอายุและคำตอบหลายคำถาม การส่งเสียง/ภาพ/ไฟล์ด้วย Telegram จำลอง รวมถึง Git diff/commit/undo และ PR บน local bare remote โดยจำลองคำสั่ง GitHub

ยังไม่ยืนยันการแนบไฟล์หรือส่งเสียงผ่าน Telegram จริง: เครื่องมือควบคุมไม่สามารถเข้าถึงช่องชื่อไฟล์ในหน้าต่างเลือกไฟล์ Windows ได้ ไม่ได้ทดสอบ PR กับ GitHub จริง โทรศัพท์จริง macOS หรือ installed app การทดสอบครั้งนี้ไม่ได้ commit หรือ push repository หลัก

## ภาพผ่าน Telegram จริง 3 พฤศจิกายน 2026

ผู้ใช้ส่งภาพเข้าบอตขณะเลือก Codex session ของ `hub-full-20261101-b` อยู่ แอปบันทึกภาพไว้ใน `.uncle/inbox` และส่ง path ไปยัง Agent; Codex ระบุรายละเอียดภาพตรงกับไฟล์ที่บันทึกจริงและตอบกลับผ่าน Telegram ตรวจ `git status` ของโปรเจกต์ทดสอบแล้วไม่มีการแก้ไฟล์ที่ติดตาม กรณีนี้ส่งภาพโดยไม่มี caption จึงใช้ข้อความเริ่มต้นของแอป ยังไม่ได้ยืนยัน caption, เอกสารแนบ หรือเสียงผ่าน Telegram จริง

ตรวจอัตโนมัติการอนุมัติข้ามหน้าต่างเพิ่มเติม: เชื่อมแกน Agent กับ Telegram จำลอง ทดสอบตอบจากคอมแล้วปุ่ม Telegram ใช้ซ้ำไม่ได้ และตอบจาก Telegram แล้วคอมตอบซ้ำไม่ได้ ชุด `npm test` ผ่าน 196 ข้าม 3 ล้มเหลว 0 ยังต้องยืนยันหน้าต่างคอมและ Telegram จริงร่วมกัน
